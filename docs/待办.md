### 已确立的核心规则（新对话不必重新推理）

1. **单一主动条（v0.11 修订）**：每张卡一个行动条；充满 → 执行**主动行动 = 只结算 `abilities` 中 `kind: active` 的条目**（按书写顺序）；全部结算完才重新累积；`everyN` 为唯一计数变体（引擎用 actionCount 计数）；主动效果**无** trigger/cooldown/priority 字段。**卡牌没有内置普攻/基础行动**（v0.11 已移除），任何伤害都必须由效果条目显式声明；`stats.atk` 只是可被 `{ ref: self.atk }` 引用、可被 buff 的数值。**卡牌只有主动与被动两种效果，可以只有主动、或只有被动**。**主动 / 被动只由 `cooldown` 决定，与 `abilities` 内容无关（v0.24 决议）**：`cooldown !== -1` 就是主动卡（没有 `kind: active` 也照常使用并广播 `afterAction`），`cooldown: -1` 就是纯被动卡（写了 `kind: active` 也完全无效、不受充能影响）；两种情况**都不报错、不新增错误码**。✅ 引擎已对齐（v0.23：`engine/tick.ts` 的 `buildActiveAction` 已删除自动普攻拼接，`simulator/demo-deck.ts` 五张卡补了显式 `dealDamage`；v0.24：新增 `afterAction` 广播），**待 RW 验收**。
2. **cooldown**：卡面**顶层必填字段**（秒）；充满周期 = cooldown × (cdp ÷ 100) ÷ 速度倍率（speed 缺省 1 × 加速2/减速0.5/冰冻0；cdp 为冷却百分比系数约定字段，缺省 100、修正加算）；**= -1 表示纯被动物品**（无行动条、无主动行动）。
3. **废除**：召唤体系（summon/moveCard/stealStat/onCardSummoned/summonDepth）、applyEffect 原语、主体效果/基础行动（baseAction/activeAction）、主动技独立 cooldown、onEveryAction 等表外时机词。
4. **8 动作原语 + 1 登记**：dealDamage / healPlayer / gainStat / shield / applyStatus / charge / destroy / repair；持续效果（灼烧/剧毒/再生）为引擎内置周期触发器，卡面用 `gainStat`（stat: burn/poison/regen，目标玩家）施加层数。第 9 原语 `enchant`（施加附魔）已登记接口、**实现搁置**（校验暂拒绝，规则 §9.9）。
5. **效果数值书写规则**：abilities / enchant 内数值型参数（amount/seconds/duration）**禁止字面量**，必须 `{ ref: self.<stat> }` 引用（可简写 `self.<stat>`）；字面量只允许在表达式内部（系数/阈值）和结构性参数（everyN/stackLimit/priority/condition 阈值）。
6. **附魔（enchant）**：常驻效果组（存在即生效，无时机词/条件），一张卡同时至多一个、新附魔覆盖旧的（无槽位、无叠加）；字段名统一为 `enchant`，结构为动作列表。
7. **超时与平局**：到达 MAX_TICK（180s）判平局，平局判我方（模拟发起方，sideA）胜；不再按血量比例判定。
8. **技能**：携带数量无上限；priority 缺省 5、范围 1–10；与卡牌被动同优先级时技能后结算（加载顺序最低）；**技能自带 stats 开放数值表**，效果数值禁止字面量、引用本技能 stats；高频时机与卡牌同等走 §6.3 单 tick 去重（每 tick 一次、多余顺延），不另设节流。
9. **状态相互作用（18.8）**：加速/减速/冰冻独立计时、不互相覆盖；冰冻期间加减速不生效但时长照减。
10. **stats 开放数值表**：atk 必填；speed 选填（缺省 1）；自定义字段自由命名，约定：shd 护盾 / hel 治疗 / bur 燃烧 / poi 剧毒 / reg 再生 / has 加速时长(s) / sol 减速时长(s) / fre 冰冻时长(s) / chg 充能时长(s) / cdp 冷却百分比系数（缺省 100）。
11. **品质继承（inherit_override）**：从最低品阶下一阶到最高品阶每阶一段、必须齐全；stats 为**增量**（该品阶基础值 = 最低品阶基础值 + 沿途增量之和，不清空局外养成）；abilities 按**卡内唯一 id** 合并覆盖（condition/actions 全写，kind 沿用）；其余字段一律继承不可覆盖。abilities 条目 id 自 v0.9 起必填。
12. **持续效果通道**：灼烧/剧毒/再生走引擎独立通道（规则 §18.9）：实例 = kind + stacks + duration（缺省常驻）+ source + enter?/exit?；生命周期 = 施加 → 进入效果 → 周期结算（0.5s/1s 不变）→ 层数归零/净化/到期 → 退出效果 → 移除。玩家侧数据维护见《玩家数据维护.md》。
13. **其他**：rarity = 最低品质；description 选填（风味描述）；destroy 为失效（仍占位）、repair 复原；卡牌无血量，玩家血量定胜负。
14. **时间模型（v0.19 两级颗粒度，规则书尚未同步）**：**全局时钟 0.01s（= 1cs）**管一切连续量（行动条/冷却推进、灼烧 0.5s 与剧毒·再生 1s 的周期、状态与 buff 时长、`chg`）；**触发器帧 0.2s** 只管"该不该触发被动/技能"的结算时机；**1 触发帧 = 20 全局帧**。拆两级的硬理由是 0.5s ÷ 0.2s = 2.5 除不尽，单颗粒度会让 debuff 相位在"隔 2 帧 / 隔 3 帧"间抖动。**所有数值量为整数**：时间以 cs 计（YAML 写秒、两位小数，换算后必为整数）、`gauge` 以 cs 计（`gauge += 1`/全局帧，满则 `gauge -= period` 结转余量）；**单次中间结果一出现小数就四舍五入、之后按整数算**（如 `period = round(cooldown_cs × cdp ÷ 100 ÷ 速度倍率)`）。**唯一豁免 = 灼烧层数**（-20%/跳 指数衰减，每跳取整会 1×0.8→round 回 1 永不衰减），该累加器内部保留小数，只在对外读取（算伤害/日志/界面/条件比较）时取整，清除阈值用"层数 < 0.01"。MAX_TICK = 900 触发帧 = 180s。
15. **帧内固定执行序（v0.19）**：每个触发帧内推进 20 个全局帧 —— 0a 持续效果与状态计时（**先递减时长再判到期**）→ 0b 行动条推进（满则记下待行动）→ 0c 帧关闭；帧边界（`globalTick % 20 === 0`）依次做 ① 满条者按 §6 优先级排序后执行主动行动 ② 触发栈批量结算（收集 → 优先级降序排序 → 逐条 apply）③ 胜负判定。结算过程中新产生的事件**并入下一个触发帧**。
