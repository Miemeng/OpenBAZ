# 玩家数据维护说明 — 战斗内玩家状态数据规范

> 版本：v0.1（持续效果通道版）
> 依据：《规则说明书 v0.10》（§3 / §9 / §11 / §14 / §18）、《卡牌模拟器框架设计 v0.14》§4.3 / §4.6（框架 v0.13 仅新增 §2.5 仓库形态与运行边界、v0.14 仅新增 §2.5.3 工具链决策，均不影响本文档）
> 读者：引擎开发者；表现层（血条 / 护盾套层 / 状态图标）以此为准渲染
> 定位：本文档枚举**战斗内引擎必须为每名玩家维护的全部数据**及其维护规则；卡牌侧状态（行动条、buff 等）挂在 BoardCard 上，见框架 §4.2 / §4.6，此处仅作交叉引用。

## 1. 总览

| 数据项 | 类型 | 初始值 | 维护者 | 规则出处 |
|--------|------|--------|--------|----------|
| `side` | 'A' / 'B' | 摆盘时确定 | 引擎 | 框架 §4.3 |
| `hp` / `maxHp` | number | 阵容文件声明（decks/*.yml 每方 hp） | 引擎 | 规则 §3 |
| `shield` | number | 0 | 引擎 | 规则 §9.4 |
| `effects` | StatusEffect[] | `[]` | **引擎独立通道** | 规则 §18.9 |
| `skills` | SkillInstance[] | 阵容声明的技能 id 列表 | 引擎 | 规则 §12 |

胜负读取点：任一方 `hp ≤ 0` 立即结束；到达 MAX_TICK（900 tick）判平局、平局判我方胜（规则 §3）。

## 2. 血量 hp / maxHp

- `maxHp` 由阵容文件在开局时声明，随后在战斗中进行维护。
- `hp` 变动只有三个入口：**伤害**（dealDamage / 灼烧 / 剧毒，先扣护盾后血量，溢出丢弃，规则 §9.1）、**治疗**（healPlayer，不超 maxHp，满血仍结算净化，规则 §9.2）、**再生**（持续效果通道每 1s 净值结算）。
- 每次 hp 变动必须写动作日志（实际变动量、来源、类型），供回放与 `onPlayerDamaged` / `onPlayerHealed` 事件参数。

## 3. 护盾 shield —— 单一护盾池

- **每个玩家只有一个护盾值**（`shield: number`），置于玩家身上，显示在血条上方；无多盾条方案。
- 变动入口：`shield` 原语（总额累加，规则 §9.4）；伤害结算时按类型抵扣——普通伤害 1 盾抵 1 伤、灼烧 1 盾抵 2 伤、**剧毒无视护盾**。
- 缺省**永久**；卡面可用 `duration` 声明限时盾（到期 tick 边界移除）。
- 抵扣后 `shield` 不为负；普通伤害击穿护盾时溢出到血量，并广播 `onShieldBroken`（参数 `overflow`）。

## 4. 持续效果通道 effects[] —— 引擎单独维护

不走卡牌触发器体系，由引擎按 **§18.9 通道**维护生命周期。每个实例：

| 字段 | 说明 |
|------|------|
| `kind` | `burn`（灼烧）/ `poison`（剧毒）/ `regen`（再生） |
| `stacks` | 层数；灼烧每 0.5s 跳伤后 **-20%**（衰减），剧毒 / 再生不衰减 |
| `duration?` | 持续 tick 数（与 `gainStat.duration` 同单位）；**缺省常驻**，直至层数归零或被净化 |
| `source` | 来源 instanceId / skillId |
| `enter?` / `exit?` | 进入 / 退出效果动作组（选填，各结算一次） |

维护规则：

1. **施加**：`gainStat`（`stat: burn/poison/regen`，目标玩家）→ 层数叠加（同 kind 同 source 叠加并刷新 duration；不同 source 各自计时）→ 进入效果 → 写日志。
2. **周期结算**（0.01s 精度时间轴，固定相位保证确定性）：灼烧每 0.5s 跳伤（先扣护盾，2 伤/1 盾）并衰减；每 1s 剧毒与再生做**一次净值结算**（先加后减，合并为一次数值变动）；同 tick 多效果到期时灼烧最优先（先 debuff 后 buff，规则 §18.8）。
3. **移除**（三途径：层数归零 / 治疗净化 / duration 到期）：先结算退出效果（走正常结算栈，可再触发触发器），再移除实例；净化量按层数削减（每 X 治疗清 0.05X 层灼烧与 0.05X 层剧毒，规则 §18.2）。
4. 实例的进入 / 退出在整个生命周期中**各只执行一次**。

## 5. 技能实例 skills[]

- 开局由阵容文件声明（数量无上限，规则 §12）；战斗内**不增不减**（无换装机制）。
- 每个实例维护 `useCount` / `triggerCount`（仅统计 / 日志，无机制含义）；触发结算受 §6.3 单 tick 去重约束（同一技能同一时机词每 tick 最多一次，多余顺延）。
- 优先级缺省 5、范围 1–10；同优先级时技能后于卡牌被动结算（加载顺序最低）。

## 6. 卡牌侧状态（交叉引用，非本文档维护范围）

以下为提醒项，数据挂在 BoardCard / 卡牌 buff 表上，引擎同帧维护：

- 行动条 `gauge` / `actionCount`（cooldown、cdp、速度倍率推进，规则 §5）
- 失效标记 `destroyed`（不推进、不行动、被动停用，数据保留，规则 §9.7）
- 卡牌状态 `cardEffects`（加速 / 减速 / 冰冻，独立计时互不覆盖，规则 §9.5 / §18.8）
- 属性 buff / debuff（gainStat 挂在卡上的层数表，stackLimit 替换最早层，规则 §9.3 / §11）
- 附魔 `enchant`（常驻效果组，单槽覆盖，规则 §18.7）

## 7. 表现层读取建议

- 血条：`hp / maxHp`；护盾套层：`shield`（消耗时同步缩减）。
- 玩家头像侧状态图标：`effects[]` 按 kind 显示层数角标，悬浮窗显示 source / duration 剩余。
- 持续效果跳字与结算节奏以引擎日志为准（回放逐 tick 可复现）。
