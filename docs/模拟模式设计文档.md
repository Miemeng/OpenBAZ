# 模拟模式 · 设计文档

> 版本：v1.0（2026-10-01）
> 依据：《异步自走棋卡牌模拟器 · 框架设计方案 v0.4》《用户故事（用户故事 1、3）》
> 定位：本文档是客户端 `client/modes/simulate/` 的实现设计，覆盖用户故事 1（拖拽摆盘对战模拟）与用户故事 3（加载外部卡包进行模拟）。

---

## 1. 概述

### 1.1 目标

模拟模式是玩家进入游戏后的核心玩法入口：加载卡牌库（内置卡包 + 外部导入卡包 + 自制草稿卡），通过拖拽完成敌我双方摆盘与技能配置，调用战斗引擎跑出**确定性结果**，并以可视化回放呈现整场战斗，帮助玩家快速验证阵容搭配与卡牌强度。

### 1.2 设计约束（继承自框架）

| 约束 | 说明 |
|------|------|
| 引擎与表现分离 | 客户端不实现任何战斗逻辑，只负责收集输入、调用引擎、渲染日志。战斗规则的一切变更只改 `engine/` |
| 确定性 | 同阵容 + 同种子 → 同结果。客户端不引入任何非种子化随机 |
| 零依赖复用 | 模拟模式与 CLI 模拟器共用同一引擎、同一注册表，客户端专属逻辑只存在于表现层 |
| YAML 热加载 | 卡牌增删改保存即生效；加载失败不崩溃、不影响进行中的对局 |

### 1.3 非目标

- 不做事件模式（模拟游戏全流程，框架中明确留接口暂不做）
- 不做卡牌/卡包创建（属自定义模式，见《自定义模式设计文档》）
- 不做网络对战、排行榜、存档云同步

## 2. 模式状态机

模拟模式在内部划分为三个互斥状态，全部界面行为由状态机驱动：

```
        ┌─────────────┐   点击「开始模拟」    ┌─────────────┐
        │  EDIT 编辑态 │ ──────────────────▶ │ RUN 战斗结算态 │
        └──────┬──────┘                     └──────┬──────┘
               │ ◀──────────── 「重新摆盘」          │
               │                                  ▼
               │                            ┌─────────────┐
               │   「重新摆盘」               │ REPLAY 回放态 │
               └──────────────────────────── │ （结算完成后）│
                                             └─────────────┘
```

| 状态 | 允许的操作 | 禁止的操作 |
|------|-----------|-----------|
| EDIT | 浏览/筛选卡牌、拖拽摆盘、配置血量与技能、导入卡包、开始模拟 | 回放控制 |
| RUN | 无（引擎同步/异步结算中，显示进度） | 一切编辑操作 |
| REPLAY | 播放/暂停、逐 tick 步进、跳转、调速、回到编辑态 | 修改阵容（需先回 EDIT） |

**状态切换原则**：编辑态 → 回放态必须经过一个完整的引擎结算（RUN 是瞬态），保证回放的数据来源是同一份不可变的战斗日志，而不是边算边播的"活"状态。

## 3. 界面布局与区域职责

```
┌────────────────────────────────────────────────────────────────┐
│ 顶栏：模式名「模拟模式」  卡包来源切换  导入卡包  种子输入  [开始模拟] │
├───────────────┬──────────────────────────────────┬─────────────┤
│               │        敌方区域（B 侧）            │             │
│               │  头像+血量条  ○技能○技能           │             │
│               │  ┌─10 格摆盘行─┐                  │             │
│               │  □ □ □ □ □ □ □ □ □ □              │   战斗信息   │
│               ├──────────────────────────────────┤   面板      │
│               │        己方区域（A 侧）            │  （可选）   │
│  卡牌列表      │  头像+血量条  ○技能○技能           │             │
│  （可筛选、    │  ┌─10 格摆盘行─┐                  │             │
│  可拖拽）      │  □ □ □ □ □ □ □ □ □ □              │             │
│               ├──────────────────────────────────┤             │
│               │  回放控制条（REPLAY 态显示）         │             │
├───────────────┴──────────────────────────────────┴─────────────┤
│ 状态栏：加载结果回显 / 校验错误提示 / 当前状态提示                    │
└────────────────────────────────────────────────────────────────┘
```

### 3.1 卡牌列表（左侧）

- **数据来源**：`CardRegistry` 当前全部已注册卡牌（`getAll()`），含内置卡包、已导入卡包、草稿卡（见 6.3）。
- **条目渲染**：卡名 + 品阶色卡框缩略图 + size 标识（小/中/大）+ 关键数值（atk / cd）+ 标签。条目可拖拽（HTML5 Drag & Drop 或指针事件实现，需兼容 Electron）。
- **筛选器**：
  - 品阶筛选：多选，来源 `rarities.yml` 动态生成（含自定义品阶）；
  - 标签筛选：多选，来源当前卡库所有 `tags` 与 `hidden_tags` 的并集；
  - 卡包来源筛选：单选（全部 / 某卡包），便于区分内置与导入内容（对应用户故事 3）；
  - 文本搜索：按卡名/id 模糊匹配。
- **数量限制**：摆盘不限制同名卡数量（同名卡生成不同 `instanceId`），列表不做张数扣减。

### 3.2 摆盘区（中央，双方各一行 10 格）

- 每侧为一行 10 格，格宽固定；卡牌按 `size` 占连续格（小 1 / 中 2 / 大 3，可被卡面 `slots` 覆盖）。
- 拖拽悬停时以占格高亮预览合法/非法落点：
  - **合法**：目标连续格全部为空且不越界；
  - **非法**：越界或与已摆卡牌重叠 → 落点标红，松手不放置并提示原因。
- 已放置卡牌显示：卡面图、品阶卡框、当前属性行（atk / cd）、被动层数角标（编辑态恒为 0，回放态显示实时值）。
- 交互：
  - 拖动已放置卡牌 = 换位置（原位置立即腾空，校验同上新落点）；
  - 右键/长按 = 移除回列表；
  - 点击 = 打开悬浮细节窗（数值行 + CD 标注 + 效果描述，见《卡牌设计细化.md》）。
- **摆盘不校验强度**，只校验几何合法性；阵容强度由玩家自行通过模拟验证。

### 3.3 玩家与技能区（摆盘行两端）

- **头像 + 血量条**：显示 `hp` / `maxHp`，可点击编辑（EDIT 态可输入双防血量，默认 1000）。
- **技能圆形图标**：置于头像两侧（对应用户故事 1"技能以圆形显示，置于头像两侧"）。
  - EDIT 态：点击圆形图标打开技能选择弹层（来源 `skills/` 注册表，支持搜索），已选技能显示为点亮图标、未选为暗色空位；
  - 携带数量：默认不限，UI 上做软展示上限（一行最多环绕头像显示 N 个，超出折叠为 "+n"），全局上限机制待定（见第 10 节）；
  - REPLAY 态：技能被触发当次，图标高亮（如描边发光）一瞬，并伴随触发计数角标 +1。
- 技能详情悬浮窗与卡牌共用样式，显示触发器、条件与动作回显文本。

### 3.4 回放控制条（REPLAY 态显示）

- 播放 / 暂停；
- 逐 tick 步进（▶| 前进 1 tick，|◀ 后退 1 tick）——**后退通过重新从头结算到目标 tick 实现**，不缓存中间态快照；
- 进度条拖动跳转（同样走重算）；
- 调速：0.5× / 1× / 2× / 4×（仅影响表现，不影响日志内容）；
- tick 计数显示（如 `tick 132 / 847`）。

### 3.5 战斗信息面板（右侧，可选折叠）

- 实时动作日志滚动（数据源 `BattleState.log`）：`[t132] 烬狼 行动 → 对敌方玩家造成 45 伤害`；
- 双方伤害统计条（累计造成伤害 / 治疗 / 护盾吸收）；
- 触发器栈当前深度（调试用，默认折叠）。

## 4. 核心交互流程

### 4.1 进入模式与卡包加载（用户故事 1 / 3 共用入口）

```
进入模拟模式
  → 引擎侧 registry 已自动加载 packs/（内置 core + 已放置的外部卡包）与 skills/
  → 客户端请求卡牌全量列表 + 技能全量列表
  → 状态栏回显加载结果：「已加载卡包：core(v1, 24 卡) / 星辉扩展包(v2, 12 卡)；技能 6 个」
  → 若存在加载失败文件：状态栏列出 文件 + 行号 + 字段路径，旧版本继续可用
```

### 4.2 导入外部卡包（用户故事 3）

1. 顶栏「导入卡包」→ 文件选择（支持选择 `.zip` 或文件夹，取决于平台能力）；
2. 复制/解压至 `packs/<pack_id>/`（与内置卡包同目录规范）；
3. 走与热加载同一套管线：YAML 解析 → schema 校验 → 注册；
4. **校验与提示**：
   - 卡包 `pack.yml` 元信息缺失或字段非法 → 拒绝导入并说明；
   - 卡牌 id 与已有卡包冲突 → 提示冲突清单，由玩家选择「覆盖 / 跳过 / 取消」（默认取消，避免误覆盖自制内容）；
   - 卡包声明依赖其他卡包（引用其卡牌/技能）而依赖缺失 → 标记该卡包为"不完整"，卡牌列表中置灰并注明缺失项，**不阻止导入但阻止其不完整卡上阵**；
   - 版本号低于本地已存在的同 id 卡 → 提示"本地版本更新"，默认保留本地。
5. 导入成功后卡牌列表新增卡包来源筛选项。

### 4.3 摆盘与技能配置

玩家完成：双方摆盘（可留空位，甚至某方 0 卡——引擎直接按胜负判定规则结算）+ 双方血量 + 双方技能勾选。界面提供：

- 「清空」按钮（分侧）；
- 「镜像阵容」按钮（B 侧一键复制 A 侧，便于自测对打）；
- 「保存阵容 / 读取阵容」：读写 `decks/*.yml`（与 CLI 共用格式），支持在 CLI 中复现同一场对局。

### 4.4 开始模拟（EDIT → RUN → REPLAY）

```
1. 客户端校验：摆盘几何合法性（引擎同一套校验函数，客户端调用 engine 暴露的 validate 工具，不自行实现规则）
2. 组装 BattleInput：
   - seed：顶栏种子输入框（留空则随机生成一次并回显，之后本场固定）
   - sideA / sideB：cards（cardId + slot）+ skills（skillId 列表）+ hp / maxHp
3. 调用引擎 runBattle(input) → 返回 BattleState.result + 全量 ActionLogEntry[]
4. 切换到 REPLAY 态，回放器从 tick 0 开始驱动渲染
```

**确定性保障**：回放渲染只消费日志，不二次调用引擎；种子在整场回放期间固定展示于界面角落，方便玩家记录与分享"阵容 + 种子 → 结果"。

### 4.5 战斗表现与回放渲染

回放渲染器以 tick 为单位消费日志（每 tick = 0.2s，见框架第 5 节），映射到视觉元素：

| 日志事件类型 | 渲染行为 |
|-------------|---------|
| `gauge` 推进 | 卡面纵向百分比进度条按当前 tick 的 gauge 值插值填充（表现层换算，不逐日志刷） |
| 卡牌行动 | 卡面攻击动作（位移动画）+ 对方血量条扣减 + 飘字伤害数字 |
| 玩家技能触发 | 头像侧圆形图标高亮一瞬 + 触发计数角标 +1 |
| 被动触发 | 卡面被动计数条更新 + 层数角标变化 |
| `gainStat` | 卡面数值行实时刷新，变化值短暂高亮 |
| `shield` | 血量条外加护盾套层，被消耗时套层同步缩减 |
| `destroy` / `repair` | 失效（卡牌灰暗、被动停用）/ 复原渲染；仍占位，棋盘格占用不变 |
| 胜负判定 | 败方血量条归零动画 + 结算遮罩（胜方 / 平局 / MAX_TICK 超时判平局且平局判我方胜） |

**渲染与引擎的边界**：动画时长、缓动曲线、飘字样式全部由表现层决定；引擎日志只携带"发生了什么、发生在哪个 tick、数值多少"。

## 5. 数据结构与接口约定

### 5.1 客户端与引擎的交互接口

```typescript
// 引擎暴露（engine/ 包，客户端唯一依赖面）
interface EngineApi {
  listCards(): CardListItem[];              // 注册表全量（含版本、品阶、标签）
  listSkills(): SkillListItem[];
  validateSetup(input: BattleInput): ValidationError[];  // 摆盘几何 + 引用完整性校验
  runBattle(input: BattleInput): BattleOutcome;          // 同步返回 result + log
  // 大日志场景预留：runBattle 可返回惰性日志读取器，回放器按需拉取
}

interface BattleInput {
  seed: number;
  sideA: SideInput;   // { hp, maxHp, cards: { cardId, slot }[], skills: string[] }
  sideB: SideInput;
}

interface BattleOutcome {
  result: 'winA' | 'winB' | 'draw';
  ticks: number;
  log: ActionLogEntry[];   // 全量动作日志，回放的唯一数据源
}
```

### 5.2 客户端内部状态（EDIT 态草稿）

```typescript
interface SimulateDraft {
  seedInput: string;            // 文本框原始值，开始时解析/生成
  sideA: SideDraft;
  sideB: SideDraft;
}
interface SideDraft {
  hp: number;
  skills: string[];                                   // 技能 id 列表
  placements: { cardId: string; slot: number }[];     // 摆盘（与 decks/*.yml 同构）
}
```

- EDIT 态所有修改只写 `SimulateDraft`，点击「开始模拟」时才转为 `BattleInput`；
- 「保存阵容」直接序列化 `SimulateDraft` 为 `decks/*.yml`，与 CLI 的 `--deckA/--deckB` 参数互通。

## 6. 数据来源与热加载在模拟模式中的体现

### 6.1 卡牌库

- 内置卡包 `packs/core` 进入模式时保证已加载（用户故事 1 验收项）；
- 外部卡包经 4.2 流程进入 `packs/`，与内置卡同权参与选卡（用户故事 3）；
- 草稿卡（`drafts/`）经自定义模式校验通过后同样出现在卡牌列表，来源筛选器中独立分组——草稿卡允许上阵，是自定义模式"测试"闭环的入口。

### 6.2 技能库

- 来源 `skills/`，与卡牌同一套热加载/注册机制；
- 技能在 EDIT 态通过圆形图标配置，数量无硬限制（软展示上限见 3.3）。

### 6.3 热加载的界面反馈

- 对局进行中（RUN/REPLAY）文件变更：不影响当前回放（引擎注册表版本隔离，框架第 9 节）；
- EDIT 态文件变更：卡牌列表/技能列表增量刷新；若变更导致当前草稿引用的卡 id 消失或 version 变化 → 该摆放项标黄提示"定义已变更"，开始模拟前强制玩家确认（重新校验）；
- 状态栏常驻最近一次加载回显（格式同框架 9.5 节示例）。

## 7. 异常与边界处理

| 场景 | 处理 |
|------|------|
| 某方 0 卡或格子大量留空 | 允许开始；结果由引擎规则自然产生（如 MAX_TICK 超时判平局、平局判我方胜） |
| 同名卡多张上阵 | 允许；生成不同 `instanceId`，回放中按 instanceId 区分 |
| 自定义品阶/卡框资源缺失 | 回退到品阶纯色卡框，状态栏警告一次，不阻塞对局（表现层资源不影响战斗逻辑） |
| 导入卡包引用的技能/卡牌缺失 | 不完整标记（4.2），对应卡上阵时 validateSetup 拦截并说明缺失项 |
| 引擎校验失败 | 开始按钮禁用 + 错误清单定位到具体卡牌/格子 |
| 战斗超 MAX_TICK | 引擎按规则判平局（平局判我方胜），回放正常结束并在结算遮罩注明 |
| 回放中途卡文件变更 | 不回溯、不重算，当前回放保持完整可播完 |

## 9. 里程碑衔接

模拟模式对应框架里程碑 **M6**（客户端模拟模式：拖拽摆盘 + 回放 + 品阶卡框渲染，用户故事 1 可演示）。建议实现顺序：

1. **S1**：布局骨架 + 卡牌列表/筛选 + 静态摆盘（不依赖引擎动画）；
2. **S2**：接入引擎 `runBattle`，战斗表现实时渲染（不等回放控制条）；
3. **S3**：回放控制条（步进/跳转/调速）；
4. **S4**：技能圆形图标配置与触发高亮；
5. **S5**：导入卡包流程与冲突/依赖提示；
6. **S6**：阵容保存/读取、种子回显、细节悬浮窗打磨。

S2 完成即可演示用户故事 1 主流程；S5 完成覆盖用户故事 3。
