## 1. 术语表

**基础设定表**
模拟器模拟的为一款异步自走棋游戏《大巴扎》异步自走棋，目前实现部分只考虑战斗部分，不考虑游戏全过程。

| 术语 | 定义 |
|------|------|
| 玩家 | 指玩家所操控的角色，基本等同于“英雄”，“角色”|
| 场地 | 每名玩家所拥有的区域，包含卡牌区域和技能区域|
| 卡牌区域 | 玩家放置卡牌的区域，大小为1*10|
| 卡牌 | 玩家所持有的道具，没有血量，在战斗开始前，将卡牌不重叠的放置在卡牌区域，开始对战，卡牌有三种大小，各自占据1，2，3格|
| 技能区域 | 在正常模式下，技能是无法移动或修改的，在模拟模式可进行调整|
| 品质 | 品质分为多种，且低品质可合成高品质，技能和卡牌共享品质定义|

| 术语 | 定义 |
|------|------|
| tick | 时间单位，1 tick = 0.2 秒；只约束触发器结算时机，持续效果与状态计时按 0.01s（厘秒，cs） 精度流逝，每个触发器每个tick最多触发一次，（同一触发器如果一个tick内多次触发，只触发一次，其他次数放在下一个tick，直到没有触发积累 |
| 行动条 / gauge | 卡牌行动进度条，充满即执行主动行动 |
| 冷却（cooldown） | 卡牌的行动条充满周期（秒，卡面顶层必填字段），主动行动的时间基准；= -1 表示纯被动物品（无行动条、无主动行动）；充满周期 = cooldown × (cdp ÷ 100) ÷ 速度倍率（见 §5） |
| 主动行动 | 行动条充满时执行的动作序列：`abilities` 中 `kind: active` 的条目按书写顺序依次结算。**卡牌没有内置的普攻/基础行动**，任何伤害与效果都必须由效果条目显式声明 |
| 主动效果（active） | 挂靠在主动行动上的效果（`abilities` 中 `kind: active` 的条目），行动条充满时按书写顺序依次触发；可声明 `everyN` 变为每第 N 次主动行动触发 |
| 被动（passive） | 挂在卡牌上的触发器效果，按优先级规则入栈结算 |
| 技能（skill） | 属于玩家（阵营）的触发器效果，无冷却，满足条件即结算 |
| 本家 | 事件归属方（如己方玩家受伤事件中的己方） |
| 相邻 | 同侧一行格子索引相邻（每人一行 10 格） |
| MAX_TICK | 防死循环的 tick 上限，暂定180s |

## 3. 玩家、血量与胜负

- 卡牌：卡牌可视为玩家的装备，`destroy` 效果可临时移除玩家的装备。
- 玩家血量是胜负条件；效果直接作用于对手玩家或双方卡牌。
- **胜负判定**：
  1. 任一方 hp ≤ 0 → 立即结束，对方获胜；
  2. 到达 MAX_TICK → 判定**平局（`draw`）**【v0.8 决议】；平局视为**我方（模拟发起方）获胜**；
  3. 双方同时归零 → 平局（`draw`）。

## 4. 战斗主循环

```
初始化：按阵容摆盘 → 广播 battleStart → 按优先级结算触发栈
循环（tick++，上限 MAX_TICK）：
  1. 所有卡牌行动条推进（每 tick 推进 0.2s ÷ 充满周期；充满周期 = cooldown × (cdp ÷ 100) ÷ 速度倍率）
  2. gauge 满者执行主动行动（多张同时满 → 按第 6 节优先级排序后依次行动）：
     a. 广播 beforeAction
     b. 依次结算主动效果：abilities 中 kind: active 的条目按书写顺序依次触发
        （声明 everyN 者仅在本卡第 N 的整数倍次主动行动时结算）
     c. 按 multicast 次数重复执行主动行动（默认 1）
     d. 广播 afterAction / onAction
     e. 行动产生的伤害事件广播 onPlayerDamaged
  3. drainTriggerStack()：弹出栈顶触发器（卡牌被动与玩家技能）→ 检查 condition
     → 执行 actions（新事件继续入栈，直到栈空）
  4. 检查胜负
```

- 时间模型：tick 制，0.2s/tick；tick 只约束触发器结算时机，持续效果与状态计时按 0.01s 精度流逝。
- 主动条特例：行动条于行动阶段充满的卡牌当 tick 执行主动行动；充能（charge）导致的满条于触发结算内立即执行，但同一卡牌同一 tick 最多执行一次主动行动（见 §6.3.5）。

## 5. 主动效果、被动效果与主动条

| 项 | 规则 |
|----|------|
| 单一主动条 | 每张卡牌只有一个行动条（gauge）；行动条充满即执行主动行动，卡面所有主动效果都挂靠在这一个条上，全部结算完毕后行动条重新累积 |
| 主动行动结构 | 主动行动 = `abilities` 中 `kind: active` 的条目按书写顺序依次结算。**卡牌只有主动与被动两种效果，且可以只有主动、或只有被动**：主动效果由行动条充满驱动，被动效果由触发器时机驱动，两者之外没有第三种"内置行动"（原 `baseAction` / `activeAction` / 普攻均已废除）。主动效果缺省不写 `priority`（不走被动优先级比较）；纯被动卡 `cooldown: -1` 即无行动条 |
| 主动 / 被动的判定 | **一张卡是主动卡还是被动卡，只由 `cooldown` 决定，与 `abilities` 写了什么无关**（v0.24 决议）：① `cooldown !== -1` 就是主动卡——即使一条 `kind: active` 都没写，行动条充满时也照常"使用该卡"并广播 `afterAction`（见 §6.4），只是不产生任何效果；② `cooldown: -1` 就是纯被动卡——卡面上即使写了 `kind: active` 并显示在卡面，也**完全无效**：不会被使用、不受充能影响。两种情况都**不报错、不新增错误码**（v0.24 决议：引擎不做"必须写主动效果"的校验） |
| 计时口径 | `cooldown` 为卡面顶层必填字段（秒）：= -1 表示纯被动物品（无行动条、不结算主动效果）；否则充满周期 = `cooldown × (cdp ÷ 100) ÷ 速度倍率`；`cdp` = stats 冷却百分比系数（约定字段，缺省 100 = 无修正；多个百分比修正**加算**，如减 10% 与减 5% 合计减 15%，即 cdp 被改到 85）；速度倍率 = `stats.speed`（缺省 1）× 状态系数（加速 ×2 / 减速 ×0.5 / 冰冻 = 0），加速的等效行动间隔最短不低于 1s |
| 计数变体 | `everyN`：主动效果仅在本卡第 N 的整数倍次主动行动时结算（缺省每次主动行动都结算；引擎以 actionCount 计数） |

## 6. 触发器系统与优先级

### 6.1 触发器结构

触发器 = 时机词（event）+ 可选参数（可获取场上任意数值，参数表详见《参数表设计.md》）（varN）+ 可选条件（condition）+ 动作列表（actions）。

### 6.2 结算优先级（已定规则）

1. 所有效果（主动效果，被动效果，技能）自带 `priority` 字段，**数值大者优先触发**；缺省 5，取值范围 1–10（v0.10 决议）；
2. 优先级相同，**加载早者优先**，战斗开始时，先本方后敌方，从左到右加载场上所有卡牌；
3. 行动阶段多张卡同时满足行动条件时，同用上述规则。

- 主动效果不走被动优先级比较：行动条充满即随主动行动结算；多张卡同时充满时按 1、2 条排序，单卡内效果队列按书写顺序依次结算。
- 技能无冷却，不走主动技通道。
- 技能无入场时间；优先级相同时**技能后于卡牌被动结算**（技能加载顺序视为最低）【v0.8 决议】。

### 6.3 触发器

> v0.3 重写。

1. **入栈**：时机词对应的事件发生后，所有监听该时机词且 `condition` 满足的触发器各自生成一条「触发记录」压入触发栈，不立即执行。
2. **结算延迟**：事件发生后 0.01s（1cs）起，该事件的触发记录才允许被实际结算；该延迟只约束最早结算时刻，不改变栈内优先级顺序。
3. **单 tick 去重**：同一触发器（主动效果、被动效果、技能均适用）每个 tick 最多结算一次。同一 tick 内若再次满足触发条件，超出的触发次数积累为该触发器的 `pendingCount`，在后续 tick 逐次顺延结算，直到积累清空。
4. **结算顺序**：每个 tick 的 `drainTriggerStack()` 阶段按 6.2 优先级规则弹出栈顶执行；执行动作产生的新事件即时生成新触发记录入栈，直到栈空后进入胜负检查。
5. **主动行动特例**：行动条于行动阶段充满的卡牌当 tick 执行主动行动；充能（charge）造成的满条于触发结算内立即执行；同一卡牌同一 tick 最多执行一次主动行动，重复满足顺延至下一 tick。

### 6.4 卡牌使用广播：`afterAction`（v0.24 决议）

1. `cooldown !== -1` 的卡牌每次执行主动行动，在本次行动的全部效果结算完毕后，**无条件广播一次 `afterAction`**（《时机表.md》B 类，别名 `onAction`，卡面统一写 `afterAction`）。
2. **"无条件"** = 不看这张卡有没有 `kind: active` 效果，也不看效果有没有真的改变场上状态。一张**没有写主动效果的主动卡**同样会广播——这正是"使用武器时""使用护盾物品时"这类时机的驱动来源（配合参数取"本事件的卡"，见《参数表设计.md》）。
3. 广播受 §6.3 第 3 条约束：同一触发帧内多张卡行动，`afterAction` 也只算"发生过一次"，监听者在同一触发帧最多结算一次。广播发生在主动行动阶段，其触发记录与该帧的其它事件（如 `onPlayerDamaged`）**并入同一个优先队列**，统一按 §6.2 排序后结算（事件广播的先后不影响结算顺序）。
4. `cooldown: -1` 的纯被动卡永不执行主动行动、永不广播 `afterAction`，也不受 `charge` 影响。
5. 本时机词当前由引擎 `engine/tick.ts` 的 `EVENT_WORDS` 承载。

## 8. 条件与数值表达式

### 8.1 条件（Condition）

```yaml
# 比较
{ cmp: lt, left: { ref: ownPlayer.hpPct }, right: 0.3 }   # 血量低于 30%
# 逻辑组合
{ not: <Condition> }
{ any: [<Condition>, ...] }     # 任一满足
{ all: [<Condition>, ...] }     # 全部满足
```

`cmp` 取值：`lt / lte / gt / gte / eq / neq`。

### 8.2 表达式（Expr）

| 形态 | 写法 | 说明 |
|------|------|------|
| 数字 | `45` | 字面量 |
| 引用 | `{ ref: self.atk }` 或简写 `self.atk` | 封闭引用表，见 8.3 |
| 事件参数 | `{ var: amount }` | 引用本次触发事件携带的参数，见《参数表设计.md》 |
| 计数 | `{ count: <Selector> }` | 满足选择器的目标数量 |
| 四则 | `{ add: [...] }` `{ sub: [...] }` `{ mul: [...] }` `{ div: [a, b] }` | 嵌套表达式 |

**效果数值书写规则（v0.7 决议，v0.10 扩展至技能）**：`abilities` / `enchant` / 技能 `actions` 内的数值型参数（`amount`、`seconds`、`duration` 等）**禁止字面量**，必须写成表达式并引用本卡 `stats` 字段（`{ ref: self.<stat> }`，可简写为 `self.<stat>`），保证战斗内可被 buff 修改；字面量只允许出现在表达式内部（系数 / 阈值，如 `mul: [self.atk, 0.2]`）与结构性参数（`everyN` / `stackLimit` / `priority` / condition 阈值）。

## 9. 动作原语（全集）

> 第一版最小集合 8 个（框架 §7）。每个原语：语义、参数、边界、示例。预留扩展位按 §6 流程增补。
> v0.10 登记第 9 原语 `enchant`（施加附魔，**实现搁置**，见 §9.9）。

**参数取值规则**：数值型参数（`amount`、`seconds`、`duration` 等）不接受字面量，必须经表达式引用本卡 `stats` 字段（§8.2 效果数值书写规则）；结构性参数与表达式内系数除外。

### 9.1 dealDamage — 造成伤害

| 项 | 内容 |
|----|------|
| 语义 | 对目标玩家或卡牌造成伤害；作用于玩家时扣 hp；【决议】作用于卡牌时不造成数值损失（卡牌无血量），仅广播 `onCardDamaged` 事件（携带 amount、source、target），供"受伤"类联动触发器使用 |
| 参数 | `target`（玩家或卡牌选择器）、`amount`（数字或表达式） |
| 边界 | 【决议】作用于玩家时实际伤害 = `min(amount, 当前可承受量)`，溢出部分丢弃、不产生额外事件；结算顺序为先护盾后血量（普通伤害 1 护盾抵 1 伤害，灼烧 1 护盾抵 2，剧毒无视护盾）；作用于玩家时触发 onPlayerDamaged 时机，作用于卡牌时触发 onCardDamaged 时机 |
| 示例 | `- do: dealDamage / target: enemyPlayer / amount: { mul: [self.atk, 0.5] }` |

### 9.2 healPlayer — 治疗玩家

| 项 | 内容 |
|----|------|
| 语义 | 恢复目标玩家 hp，不超过 maxHp |
| 参数 | `target`、`amount` |
| 边界 | 【决议】满血时 hp 恢复量为 0 但动作仍结算：按声明治疗量结算净化（每 X 点治疗清除 0.05X 层灼烧与 0.05X 层剧毒，见 §1 附录），并广播 `onPlayerHealed`（amount 为实际恢复量，可为 0）；日志记录实际恢复量与净化量 |
| 示例 | `- do: healPlayer / target: ownPlayer / amount: self.hel` |

### 9.3 gainStat — 属性增减

| 项 | 内容 |
|----|------|
| 语义 | 为目标增加/减少属性（atk、speed 等），以 buff 形式挂在目标上；目标为玩家且 `stat` 为 `burn / poison / regen` 时走**持续效果通道**（§18.9），可携带通道参数 |
| 参数 | `stat`、`amount`（支持负数）、`duration?`（持续 tick 数，缺省永久；对持续效果通道为实例持续时间，见 §18.9）、`stackLimit?`（层数上限）、`target`；**持续效果通道选填**：`enter?`（施加时立即结算的动作组）、`exit?`（移除时结算的动作组） |
| 边界 | 【决议】达到 stackLimit 后，新层替换同 stat、同 source 中获得时间最早的一层并刷新其时长；到期 buff 于 tick 边界移除 |
| 示例 | `- do: gainStat / stat: atk / amount: { mul: [self.atk, 0.2] } / stackLimit: 5`；通道：`- do: gainStat / stat: burn / amount: self.bur / target: enemyPlayer / duration: self.burDur / exit: [ ... ]` |

### 9.4 shield — 护盾

| 项 | 内容 |
|----|------|
| 语义 | 为目标玩家附加护盾，抵消对其伤害 |
| 参数 | `target`、`amount`、`duration?`（持续 tick 数，缺省永久） |
| 边界 | 【决议】护盾可叠加，总额累加为一个护盾值；默认无时限，卡面可通过 `duration` 声明限时；消耗顺序与获得顺序无关（合并为单一护盾池，从总额中扣除）；护盾在血条上方独立显示【是否改为多护盾条分别计时，待定，见框架 §13】 |
| 示例 | `- do: shield / target: ownPlayer / amount: self.shd` |

### 9.5 applyStatus — 施加卡牌状态（加速 / 减速 / 冰冻）

| 项 | 内容 |
|----|------|
| 语义 | 为目标卡牌施加加速（haste）、减速（slow）或冰冻（freeze）状态；三者**独立计时、不互相覆盖**（相互作用见 §18.8） |
| 参数 | `target`（卡牌选择器）、`status`（`haste / slow / freeze`）、`duration`（持续 tick 数，必填） |
| 边界 | 【决议】加速：行动条速度 ×2，但等效行动间隔最短不低于 1s（两次主动行动间隔钳制）；减速：行动条速度 ÷2；冰冻：行动条速度为 0 且无法执行主动行动；状态到期于 tick 边界移除；对 `destroyed` 卡牌施加状态静默跳过并记 warn 日志 |
| 示例 | `- do: applyStatus / status: haste / duration: 25 / target: { pick: randomOwnCard }` |

### 9.6 charge — 行动条充能

| 项 | 内容 |
|----|------|
| 语义 | 将目标卡牌的行动条直接推进 X 秒，等价于提前流逝 X 秒的 gauge 进度 |
| 参数 | `target`（卡牌选择器）、`seconds`（数字或表达式） |
| 边界 | 【决议】单次推进最多让卡牌主动行动一次（推进后 gauge 溢出部分保留，不连锁触发第二次行动）；对 `destroyed` 或 `freeze` 状态的卡牌充能静默跳过并记 warn 日志；充能触发的行动照常广播 beforeAction / afterAction / onPlayerDamaged |
| 示例 | `- do: charge / seconds: self.chg / target: { pick: adjacentToSelf }` |

### 9.7 destroy — 使卡牌失效

| 项 | 内容 |
|----|------|
| 语义 | 使场上卡牌在战斗中完全失效（唯一失效方式）；失效卡不再推进行动条、不执行主动行动、其挂着的被动触发器全部停用；触发 onCardDestroyed。卡牌仍占位在场上，**不发生退场** |
| 参数 | `target`（卡牌选择器） |
| 边界 | 【决议】目标不存在或已失效时静默跳过，记录 warn 级日志，不报错、不中断结算栈；失效不清除卡牌身上已有的 buff / debuff 数据（数据保留，标记 destroyed 期间不生效，供 repair 恢复）；同名多张卡按 instanceId 逐一选择 |
| 示例 | `- do: destroy / target: { pick: randomEnemyCard }` |

### 9.8 repair — 修复失效卡牌

| 项 | 内容 |
|----|------|
| 语义 | 移除目标卡牌的 destroyed 标记，使其恢复行动与被动结算；触发 onCardRepaired |
| 参数 | `target`（卡牌选择器） |
| 边界 | 【决议】目标未失效时静默跳过，记录 warn 级日志；恢复后 gauge 从 0 重新累积，已保留的 buff / debuff 数据立即恢复生效 |
| 示例 | `- do: repair / target: { pick: randomOwnCard }` |

### 9.9 enchant — 施加附魔【登记待实现，v0.10】

| 项 | 内容 |
|----|------|
| 语义 | 对目标卡牌施加附魔，新附魔按 §18.7 覆盖规则替换目标原有的附魔 |
| 参数 | `target`（卡牌选择器）；附魔内容的书写方式（内联动作组 / 引用施法者 stats 定义）**待设计** |
| 边界 | **实现搁置**：模拟器阶段校验器遇到 `do: enchant` 直接拒绝并提示"附魔施加暂未实现"，避免写出无法运行的卡；接口语义已登记，实现时按 §6 流程增补参数表 |
| 示例 | `- do: enchant / target: { pick: randomOwnCard }`（暂不可运行） |

## 10. 选择器（Selector，封闭词典）

用于 `target` / `slot` / `count` 等参数的目标选择。第一版草案：

| 选择器 | 语义 | 状态 |
|--------|------|------|
| `self` | 效果来源卡自身 | ✅ |
| `ownPlayer` / `enemyPlayer` | 己方 / 敌方玩家 | ✅ |
| `allOwnCards` | 全体己方场上卡牌 | ✅ |
| `allEnemyCards` | 全体敌方场上卡牌 | ✅ |
| `randomEnemyCard` | 随机一张敌方卡牌（走 rng） | ✅ |
| `randomOwnCard` | 随机一张己方卡牌 | ✅ |
| `adjacentToSelf` | 与自身格索引相邻的己方场上卡牌（左右各至多一张，返回 0–2 张） | ✅ |
| `adjacentLeftSelf` / `adjacentRightSelf` | 自身左 / 右相邻的己方卡牌（至多一张） | ✅ |

多目标结算顺序：【决议】按 slot 索引升序（从左至右）；随机类选择器先抽样、再按 slot 索引升序结算，保证可复现（同一 rng 种子结果一致）。

## 11. Buff 与层数规则

| 项 | 规则 |
|----|------|
| buff 结构 | `{ stat, delta, source, expiryTick, stackCount }` |
| 层数上限 | 由 `stackLimit` 声明；【决议】达到上限后新层替换同 stat、同 source 最早获得的一层并刷新其时长（与 9.3 一致） |

## 12. 技能（Skill）规则

| 项 | 规则 |
|----|------|
| 归属 | 技能属于玩家（阵营），不挂在任何卡上 |
| 组成 | 触发器 + 条件 + 效果列表 + **stats 开放数值表**；与卡牌共用时机词表与动作原语【v0.10 决议：技能自带 stats（atk 非必填），效果数值同样禁止字面量、一律 `{ ref: self.<stat> }` 引用本技能 stats，规则同 §8.2】 |
| 冷却/费用 | 无冷却、无费用；只要触发器满足即入栈结算 |
| 不支持的字段 | 冷却类字段（技能无冷却概念）在校验阶段直接拒绝并提示 |
| 携带数量 | 不限，每方可携带任意多个技能【v0.8 决议：无上限】 |
| 优先级 | 与卡牌被动同台比较；缺省 5、范围 1–10（v0.10 决议）；优先级相同时技能后结算（加载顺序视为最低，见 §6.2）【v0.8 决议】 |
| 高频时机 | 允许行动类高频时机（`beforeAction` / `afterAction` / `everyN`）；技能与卡牌触发器同等受 §6.3 单 tick 去重约束（同一技能同一时机词每 tick 最多结算一次，多余次数顺延），**不另设全局节流**【v0.10 决议】 |
| 统计 | `triggerCount` 仅用于统计/日志，无机制含义 |

## 13. 品阶与合成

| 品阶 | id | 颜色 | 卡框 |
|------|----|------|------|
| 青铜 | bronze | #8d6e63 | 默认 |
| 白银 | silver | #b0bec5 | 默认 |
| 黄金 | gold | #ffc107 | 默认 |
| 钻石 | diamond | #00e5ff | diamond_frame |

下述内容在`rarities.yml`中定义
- 最低品阶：卡面 `rarity` 字段表示这张卡的**最低品质**；卡牌可经合成升至更高品阶（完整模式），各品阶数值以最低品阶卡面为基础、按覆盖规则变化（见下述 inherit_override）
- 合成关系：二合一，默认`bronze → silver → gold → diamond`，合成关系在文件中进行定义
- 自定义品阶：可自定义颜色与卡框，品阶在卡牌数据中需体现；
- 合成机制在模拟模式不体现，后续完整模式进行体现。

### 13.1 品质继承覆盖（`inherit_override`，v0.9 定稿）

高品质卡不重复书写整张卡面，而是在卡面文件中以 `inherit_override` 字段声明**按品阶分段**的增量覆盖：

1. **分段齐全**：从本卡最低品阶（`rarity` 字段）的**下一阶**起、到最高品阶（默认 `diamond`）为止，每一阶一段、必须齐全；段的顺序须与合成链一致。
2. **stats 增量覆盖**：每段的 `stats` 为**增量（delta）**，可正可负；该品阶基础值 = 最低品阶基础值 + 沿途各段增量之和。增量只修改卡面基础值，**不触碰局外养成等运行时附加数值**（升品不清空养成）。
3. **abilities 按 id 合并**：`abilities` 条目须带卡内唯一的 `id`；覆盖条目只写 `id` + `condition` + `actions`（后两者全写，`kind` 沿用被覆盖条目）；未列出的条目原样继承。
4. **其余字段不覆盖**：`cooldown` / `enchant` / `tags` / 经济字段等一律继承，不可在 override 中书写。
5. 写法样例见《卡牌YAML模板.yml》v0.3.4（atk 走 10 → 20 → 40 → 80，阈值 30% → 40% → 50% → 60%）。

## 14. 边界情况决议表

| 问题 | 决议 |
|------|------|
| 时间模型 | tick 制，0.2s/tick；tick 只约束触发器结算时机 |
| 主动条计时 | 每张卡只有一个行动条；充满 → 结算主动行动全部效果 → 重新累积；主动效果无独立 cooldown 字段 |
| 格子排布 | 每人一行 10 格；相邻 = 索引相邻 |
| 血量 | 玩家血量是胜负条件 |
| 多被动结算 | priority 高 → 入场早 |
| 主动行动 | = `kind: active` 的效果条目按书写顺序依次触发；**无内置普攻、无主体效果自定义**（v0.6 废除 `baseAction` / `activeAction`，本次一并移除普攻） |
| MAX_TICK 判定 | 180s；到达即平局（`draw`），平局判我方（模拟发起方）胜【v0.8 决议】 |
| 伤害溢出（v0.3 新增） | 实际伤害 = min(amount, 可承受量)，溢出丢弃，不产生额外事件 |
| 满血治疗（v0.3 新增） | 恢复量为 0 仍结算净化，并广播 onPlayerHealed |
| buff 超层（v0.3 新增） | 替换同 stat、同 source 最早一层并刷新时长 |
| 护盾叠加（v0.3 新增） | 合并为单一护盾池，总额累加，默认永久 |
| 召唤物 / 进场退场（v0.4 新增） | 【决议】游戏内不存在召唤物，所有卡牌战斗前一次性布置完成；战斗中无卡牌进场与退场，`destroy` 为失效（卡牌仍占位），`repair` 可恢复 |
| 多目标顺序（v0.3 新增） | slot 索引升序；随机类先抽样再排序 |
| 单一主动条（v0.5 新增） | 每张卡只有一个行动条；主动行动 = `kind: active` 的效果条目按书写顺序依次触发；`everyN` 为唯一计数变体；废除主动技独立 cooldown |
| 卡牌效果只有主动与被动（v0.11 新增） | 【决议】**卡牌只有主动效果与被动效果两种，可以只有主动、或只有被动**；两者之外不存在"内置攻击/基础行动"。任何伤害（含对敌方玩家的伤害）都必须由效果条目显式声明，`stats.atk` 只是一个可被引用/被 buff 的数值，**不再隐式转化为每次行动的攻击伤害**；纯被动卡以 `cooldown: -1` 关闭行动条 |
| cooldown 顶层化（v0.6 新增） | `cooldown`（秒）为卡面顶层必填字段，即主动条充满周期：充满周期 = cooldown ÷ 速度倍率（speed 缺省 1，加速 ×2 / 减速 ×0.5 / 冰冻 = 0）；新增选填字段 `description`（风味描述，悬浮窗小字显示）；`rarity` 明确为最低品质 |
| 效果数值引用 stats（v0.7 新增） | `abilities` / `enchant` 内数值型参数禁止字面量，一律 `{ ref: self.<stat> }`（可简写 `self.<stat>`）引用 stats 字段；字面量仅限表达式内系数 / 阈值与结构性参数（everyN / stackLimit / priority / condition 阈值）；`cooldown = -1` 为纯被动物品（无行动条、不结算主动效果） |
| cdp 与品质继承（v0.9 新增） | 新增约定字段 `cdp`（冷却百分比系数，缺省 100，修正加算）：充满周期 = cooldown × (cdp ÷ 100) ÷ 速度倍率（§1 / §4 / §5）；`chg` 定为充能时长约定字段（§9.6）；品质继承覆盖 `inherit_override` 定稿：按品阶分段、stats 增量、abilities 按 id 全写覆盖、其余字段继承（§13.1） |
| priority 范围 / 技能 stats / 持续效果通道（v0.10 新增） | `priority` 缺省 5、范围 1–10（§6.2 / §12）；技能获得 stats 开放数值表，效果数值禁止字面量、引用本技能 stats（§8.2 / §12）；持续效果改走引擎独立通道：实例带层数 / duration / enter / exit，引擎维护生命周期（§9.3 / §18.9，duration 待定项随之关闭）；登记第 9 原语 `enchant`（施加附魔，实现搁置，§9.9）；`onTickStart` / `onTickEnd` 从时机表移除 |

## 18. 附录效果的触发器定义

> 本节将 §1 术语表附录中列出的全部效果（buff / debuff / 卡牌状态）落实为触发器 / 动作原语层面的正式定义。除注明"引擎内置"外，卡面书写方式与普通触发器一致。

### 18.1 总览

| 效果 | 实现方式 | 载体 | 对应定义 |
|------|----------|------|----------|
| 护盾 shield | 动作原语 | 玩家 | §9.4 |
| 治疗 heal | 动作原语（含净化） | 玩家 | §9.2 + 18.2 |
| 灼烧 burn | 引擎内置周期触发器 | 玩家 | 18.3 |
| 剧毒 poison | 引擎内置周期触发器 | 玩家 | 18.4 |
| 再生 regen | 引擎内置周期触发器 | 玩家 | 18.5 |
| 加速 haste | 动作原语 applyStatus | 卡牌 | §9.5 |
| 减速 slow | 动作原语 applyStatus | 卡牌 | §9.5 |
| 冰冻 freeze | 动作原语 applyStatus | 卡牌 | §9.5 |
| 充能 charge | 动作原语 | 卡牌 | §9.6 |
| 摧毁 destroy | 动作原语 | 卡牌 | §9.7 |
| 修复 repair | 动作原语 | 卡牌 | §9.8 |
| 多重触发 multicast | 卡牌属性（非触发器） | 卡牌 | 18.6 |
| 附魔 enchant | 卡面自定义触发器组 | 卡牌 | 18.7 |

### 18.2 治疗与净化

`healPlayer` 结算时同步执行净化：每 X 点声明治疗量清除携带者 0.05X 层灼烧与 0.05X 层剧毒（可叠加为小数层），净化在血量恢复之后结算；满血时恢复量为 0，净化照常执行（见 §9.2）。

### 18.3 灼烧 burn（引擎内置）

挂在玩家身上的 debuff，层数 `stacks` 以 cs 精度计时，每 0.5s 触发一次；事件在最近 tick 边界入栈结算（§6.3）。

```yaml
effect: burn
on: onBurnTick            # 内部周期 0.5s
actions:
  - do: dealDamage        # damageType: burn；每点护盾抵 2 点灼烧伤害
    target: <carrier>     # 携带者
    amount: { var: stacks }
  - do: gainStat          # 结算后层数衰减 20%
    stat: burn
    amount: { mul: [ { var: stacks }, -0.2 ] }
    target: <carrier>
```

层数低于 0.01 视为清除；灼烧层数可被治疗净化（18.2）。

### 18.4 剧毒 poison（引擎内置）

```yaml
effect: poison
on: onPoisonTick          # 内部周期 1s
actions:
  - do: dealDamage        # damageType: poison；无视护盾、不衰减
    target: <carrier>
    amount: { var: stacks }
```

### 18.5 再生 regen（引擎内置）

```yaml
effect: regen
on: onRegenTick           # 内部周期 1s
actions:
  - do: healPlayer        # 恢复 stacks 点血量；不产生净化（引擎调用，跳过净化环节）
    target: <carrier>
    amount: { var: stacks }
```

### 18.6 多重触发 multicast

卡牌属性而非触发器：行动条充满后连续执行 N 次主动行动（缺省 N=1）。每次行动独立广播 `beforeAction` / `afterAction`，产生的伤害各自广播 `onPlayerDamaged`；N 次行动视为同一次"行动阶段"内的连续结算，中间不插入其他卡牌的行动。

### 18.7 附魔 enchant

附魔为卡面级**常驻效果组**：存在即持续生效，无时机词与条件，书写在卡牌设定文件的 `enchant` 字段中，每项为动作（动作限 §9 原语，参数限《参数表设计.md》，数值书写规则同 §8.2）。一张卡牌的附魔效果须在卡牌设定文件中单独书写并逐条定义。

**覆盖规则（v0.8 决议）**：一张卡同时至多存在一个生效附魔；被施加新附魔时，新附魔**覆盖**旧附魔，旧附魔的效果组全部移除、不再生效。附魔槽位与叠加规则以此为准（单槽、无叠加）。

### 18.8 状态与标记的相互作用

**加速 / 减速 / 冰冻（applyStatus，§9.5）**

- 三者独立计时、互不占位，**不互相覆盖**：施加任一状态不影响其他状态的剩余时长。
- 加速与减速同时存在时效果抵消（等效速度倍率 ×1），但两者时长各自独立流逝；效果取消后剩余的一方继续生效。
- 冰冻期间加速 / 减速不生效，但两者的剩余时长照常减少。

**失效标记（`destroyed`，§9.7 / §9.8）**

- `destroyed` 卡牌：不推进 gauge、不主动行动、被动停用；applyStatus / charge 对其无效（§9.5、§9.6）；可被 repair 恢复（§9.8）。

**持续效果结算节奏（灼烧 / 剧毒 / 再生，§18.3–§18.5）**

- 三者相互独立，可同时携带并按各自周期结算。
- 每 0.5s 结算一次灼烧；每 1s 将再生与剧毒按"先加后减"做一次净值结算（再生回复与剧毒扣血合并为一次数值变动）。
- 同一 tick 内若多个持续效果同时到期，结算顺序为：灼烧最先，其次再生 / 剧毒的净值结算（先 debuff 后 buff）。


### 18.9 持续效果通道（引擎单独维护，v0.10 设计）

灼烧 / 剧毒 / 再生不走卡牌触发器体系，由引擎以**独立通道**维护生命周期。每个持续效果实例：

| 字段 | 说明 |
|------|------|
| `kind` | `burn` / `poison` / `regen` |
| `stacks` | 当前层数（施加即叠加入口，灼烧随跳伤衰减，剧毒 / 再生不衰减） |
| `duration?` | 持续时间（tick 数，与 `gainStat.duration` 同单位）；**缺省常驻**，直至层数归零或被净化 |
| `source` | 来源（instanceId / skillId） |
| `enter?` | **进入效果**：施加时立即结算一次的动作组（选填） |
| `exit?` | **退出效果**：实例移除时结算一次的动作组（选填） |

**生命周期**：施加（gainStat，层数 +amount）→ 进入效果 → 周期结算（周期与衰减规则不变：灼烧每 0.5s 跳伤并 -20% 层数、剧毒每 1s 跳伤无视护盾不衰减、再生每 1s 回血不衰减，节奏见 §18.8）→ 层数归零 / 被净化 / duration 到期 → 退出效果 → 移除。

**规则要点**：

- 同 kind 多实例可共存（不同 source 各自计时）；同 kind 同 source 再施加默认叠加层数并刷新 duration（沿用 buff 叠加决议）。
- 治疗净化（§9.2 / §18.2）按层数削减，可致实例提前进入"退出效果 → 移除"流程。
- 进入 / 退出效果产生的动作走正常结算栈，可再触发触发器，但持续效果实例本身的进入 / 退出只执行一次。
- 卡面书写：`gainStat`（`stat: burn / poison / regen`，目标玩家）+ 选填 `duration` / `enter` / `exit`（§9.3）。
